# Расписание

Веб-приложение для расписания занятий и учёта посещаемости. Панченко.

## Лаба 1 — визуальный дизайн

![Экран занятий](design/schedule.png)

Студент загружает расписание из HTML, просматривает занятия, исправляет записи,
отмечает посещение и смотрит статистику по предметам.

Три раздела: «Занятия», «Статистика» и «Импорт». Форма добавления и изменения
занятия содержит дату, время, предмет, преподавателя и аудиторию.

Отметка посещения имеет три состояния: «Был», «Не был», «Не отмечено».
В процент посещаемости входят только занятия с отметкой.

Макет создан встроенным генератором изображений. Интерфейс следующих лаб
реализуется обычными HTML и CSS; изображение служит макетом.

## Лаба 2 — интерфейс

Angular 20, TypeScript, обычный CSS. У каждого компонента своя папка и отдельные
файлы `.ts`, `.html`, `.css`. Маршруты переключает Angular Router; свойства
и события связывают шаблон с компонентом.

```sh
cd client
pnpm install --frozen-lockfile
pnpm start
```

Открыть http://localhost:4200. Требуются Node.js 22.12+ или 24 и pnpm 11.
Команда `pnpm build` собирает приложение.

Компоненты вызывают `LessonsService`: список, создание, изменение, удаление,
отметки посещения, импорт и статистика. В этой лабе сервис хранит тестовые данные
в памяти браузера: после обновления страницы изменения сбрасываются.
Формат HTML сохранён из прежнего приложения; пример доступен в разделе импорта.

## Лаба 3 — API на C#

На ветке `codex/lab3-api` интерфейс обращается к ASP.NET Core API.
Данные находятся в памяти сервера и сохраняются при обновлении страницы,
но сбрасываются при перезапуске API. Настоящая БД в этой лабе заменена заглушкой.

Нужен .NET 10 SDK. Запустить из корня в первом терминале:

```sh
dotnet run --project api
```

Во втором терминале:

```sh
cd client
pnpm install --frozen-lockfile
pnpm start
```

Интерфейс: http://localhost:4200. API: http://localhost:5080/api/lessons.
Angular перенаправляет `/api` на порт 5080 через `proxy.conf.json`.

### Как устроен код

- `Domain` — занятие с постоянным Id, его данные и правила их корректности.
- `Application` — действия с расписанием, импорт HTML и расчёт статистики.
- `Infrastructure` — реализация репозитория в памяти вместо БД.
- `Controllers` — HTTP-запросы, вызов сервиса и коды ответа.
- `tests` — модульные тесты правил и интеграционные тесты HTTP API.

Путь действия: шаблон → компонент → Angular-сервис → контроллер →
сервис приложения → репозиторий. Для замены заглушки БД нужно реализовать
`ILessonRepository` и поменять регистрацию в `Program.cs`.

### API

| Метод | Адрес | Результат |
| --- | --- | --- |
| GET | `/api/lessons` | Список: `date`, `search`, `attendance`, `page`, `pageSize` |
| GET | `/api/lessons/{id}` | Одно занятие |
| POST | `/api/lessons` | Создание: 201 и Location |
| PUT | `/api/lessons/{id}` | Изменение: 204 |
| PATCH | `/api/lessons/{id}/attendance` | Отметка или сброс: 204 |
| DELETE | `/api/lessons/{id}` | Удаление: 204 |
| POST | `/api/lessons/import` | Импорт: 200 и число добавленных занятий |
| GET | `/api/statistics` | Общая статистика и итоги по предметам |

Список выдаётся страницами по 10, максимум 100 занятий. Значения `attendance`:
`present`, `absent`, `unmarked`. Неверные данные возвращают 400,
отсутствующее занятие — 404. Импорт принимает HTML до 1 МБ и 500 занятий;
проверяется весь файл до записи. Повторная загрузка добавляет записи повторно.

### Проверка

```sh
dotnet test Raspisanie.slnx
cd client
pnpm build
```

В интеграционных тестах запускается настоящее приложение с отдельным хранилищем
для каждого теста. Проверяются CRUD и коды HTTP, фильтры и страницы списка,
валидация, сброс отметки, импорт и статистика. Также проверяется, что изменение
занятия сохраняет отметку, а неудачный импорт ничего не добавляет.

Авторизация и мобильная версия отложены до следующих лабораторных.
